Methodology

Workspace-Bench defines workspace learning as the ability to identify, reason over, update, and validate dependencies among large collections of files while producing task-correct deliverables.

Workspace Learning

Agents must understand explicit and implicit file relationships. The correct answer is often distributed across notes, comments, metadata, configuration files, archive contents, or historical versions.

Task Construction

Tasks are built from realistic workspaces and worker profiles. Each task requires the agent to interpret instructions, identify the relevant context, and produce a final output that satisfies detailed rubrics.

Rubric-based Scoring

Workspace-Bench does not reduce evaluation to a single unit test. Deliverables are graded against rubric criteria that capture evidence use, correctness, policy adherence, completeness, and consistency.

Full vs Lite Benchmark

The full benchmark contains 388 tasks. The lite split contains 100 tasks and is intended for faster repeated evaluation with lower cost while preserving representative difficulty.

Evaluation Protocol

A complete run should make the agent behavior, environment, and final outputs reproducible.

1. Workspace Setup

Initialize the benchmark workspace, selected split, and task-specific files in a controlled environment.

2. Agent Execution

Run the agent with the declared harness, model, context limits, tools, and budget constraints.

3. Output Collection

Capture logs, modified files, final deliverables, and task metadata for downstream grading.

4. Rubric Evaluation

Score deliverables against rubric criteria and aggregate into task success and overall benchmark metrics.

5. Verification

Maintain a reproducible record of runtime, cost, versioning, and the exact evaluation configuration used.

6. Release

Publish verified results with a report link and sufficient reproduction material for maintainers to inspect.

Capability Dimensions

The benchmark is designed so each dimension can fail independently.

File Dependency Discovery

Locating the right files, versions, and references under incomplete or misleading top-level cues.

Cross-file Reasoning

Combining evidence across heterogeneous artifacts to resolve ambiguity and conflicts.

Context Integration

Keeping the relevant context active while ignoring irrelevant noise in large workspaces.

Adaptive Decision Making

Choosing safe, effective actions based on workspace state, policy constraints, and deliverable requirements.

Workspace Modification

Editing or preserving files correctly without breaking dependencies or violating retention constraints.

Final Deliverable Quality

Producing outputs that satisfy rubric criteria for correctness, traceability, completeness, and consistency.

Reproducibility Requirements. Verified submissions should include the benchmark split, harness name, model identifier, runtime configuration, workspace constraints, logs, final outputs, cost and latency summary, and a stable report link that lets maintainers replay or inspect the run.
